# Results

Generated by `python -m foilnet.analysis.experiments`. Every number comes from one seeded run; the surrounding discussion is in the README.

## Setup

- 5-network deep ensembles. Members differ only in seed (`seed + i`) and use the settings in `configs/train-mlp.toml`: hidden [128, 128], tanh, lr 0.01, 400 epochs.
- Data split: 3500 train / 750 validation / 750 test, seed 0. All test numbers below use samples the networks never saw.
- Ensemble prediction is the mean of the members; its uncertainty is the sample standard deviation across members (called spread, or sigma).

## Ensemble on the held-out test set

| target | label spread | single network RMSE (mean) | ensemble RMSE | mean ensemble spread | RMS(error / spread) | Spearman(|error|, spread) |

| cl | 0.623 | 0.000779 | 0.000525 | 0.000575 | 1.24 | 0.18 |
| cm | 0.053 | 0.000181 | 0.000168 | 6.98e-05 | 2.61 | 0.21 |

RMS(error / spread) is 1 for a calibrated ensemble and above 1 when the spread understates the error. Spearman measures whether a larger spread marks the samples that really are worse (1 = perfectly, 0 = not at all).

## Solver discretisation error of the labels

RMS difference between the labels (solved with 160 panels) and a 640-panel solve of the same test samples:

| target | RMS difference | as share of label spread |
|---|---|---|
| cl | 0.000161 | 0.03% |
| cm | 0.000185 | 0.35% |

This is the distance from a converged solver, not noise: it is a smooth function of the inputs that a network can learn, and a surrogate trained on these labels inherits it relative to a converged solver.

## Speed

Solver at 160 panels against the 5-network ensemble, medians on this machine, CPU only.

| what is timed | time |
|---|---|
| solver, new shape each call (build + solve) | 15.09 ms |
| solver, same shape, new angle | 174 µs |
| ensemble, large batch, per sample | 7.0 µs |
| ensemble, one sample per call | 2632 µs |

Speed-up over a new-shape solve: about 2,169x in a large batch, about 6x one call at a time. For an angle sweep of a single shape the solver is already fast (it reuses its factorised matrix), so the surrogate's advantage there is much smaller. Timings on a laptop vary by about 2x between runs, so read them as orders of magnitude.
